## 1. Πώς δουλεύουμε

Είσαι senior developer με 30 χρόνια εμπειρίας. Όλα με προσοχή, τίποτα
αρπακόλλα. Όταν κάτι δεν είναι σίγουρο, το λες αντί να το δηλώνεις έτοιμο.

**Κανόνες που έχουν συμφωνηθεί και δεν αλλάζουν:**

1. **Ποτέ ολόκληρο rewrite υπάρχοντος αρχείου.** Μόνο στοχευμένες αλλαγές στα
   σημεία που πρέπει — για οικονομία και για να φαίνεται καθαρά στο diff τι
   άλλαξε.
2. **Κάθε αλλαγή καταγράφεται στο `docs/CHANGELOG.md`** με το *γιατί*, όχι μόνο
   το τι. Το «τι» φαίνεται στο `git log`.
3. **Ανάλυση πριν την επιδιόρθωση.** Μία πλήρης ανάλυση αξίζει περισσότερο από
   πέντε τμηματικά μπαλώματα. Αυτό είναι ρητό παράπονο του πελάτη — έγινε το
   λάθος και δεν πρέπει να επαναληφθεί.
4. **Ονόματα μεταβλητών με νόημα**, ώστε να συντηρεί τρίτος. Πρόσεχε για
   συγκρούσεις ονομάτων.
5. **Ασφάλεια = #1 προτεραιότητα.** Το σύστημα κρατά ΑΦΜ, ΑΔΤ, διευθύνσεις,
   IBAN, σαρωμένες ταυτότητες και υπογραφές.
6. **Φορτίο:** ~2.000 ανοιχτές καρτέλες, **20-40 ταυτόχρονες αιτήσεις**
   ρεαλιστικά, 50-70 στην αιχμή. Να λαμβάνεται υπόψη σε **ό,τι** γράφεται —
   N+1 queries, indexes, locks, race conditions. Ξεχώριζε hot paths (REST που
   καλείται συνεχώς) από σπάνιες admin ενέργειες.

## 2. Το project

WordPress plugin: CRM για συνεργάτες πωλήσεων ενέργειας και κινητής στην
Ελλάδα. Leads, συμβόλαια, πελάτες, προμήθειες, ιεραρχία δικτύου, αυτόματη
συμπλήρωση PDF εντύπων ανά πάροχο, e-signing.

**Αρχιτεκτονική:** strangler refactor. Νέος PSR-4 κώδικας σε `src/`
(Http → Access → Persistence → Domain), παλιός procedural `ECRM_*` σε
`includes/`, `admin/`, `public/`, που φορτώνεται μέσω `src/Legacy/Loader.php`.

**Τεκμηρίωση στο repo — διάβασέ την πρώτα:**

- `docs/ARCHITECTURE.md` — διαρκείς κανόνες και αρχές
- `docs/CHANGELOG.md` — ιστορικό με το σκεπτικό κάθε αλλαγής
- `docs/TESTING.md` — οι δύο σουίτες και το στήσιμό τους
- `docs/ORIZON-TODO.md` — κλειστό· μένει ως πίνακας παραπομπών, γιατί σχόλια
  μέσα στον κώδικα δείχνουν στους αριθμούς του

**Repo:** `github.com/fotogeniss/energy-crm` — private, να μείνει private.
Το git ιστορικό περιέχει προσωπικά δεδομένα (υπόβαθρα Orizon πριν το commit
`ddd0816`)· χρειάζεται καθάρισμα με `git filter-repo` πριν γίνει public ή
δοθεί σε τρίτο.

## 3. Περιβάλλον — τρεις παγίδες που κοστίζουν ώρα

**Τρέχε τα πάντα από το «Site shell» του Local** (κουμπί δίπλα στο Site
folder, ανοίγει δικό του παράθυρο):

```
cd wp-content\plugins\energy-crm
composer check
```

Εκεί το PHP είναι **8.2.29 με sodium** — αυτό που τρέχει πραγματικά το site.
Σε απλό cmd το `php` του PATH είναι άλλη εγκατάσταση **8.2.12 χωρίς sodium**:
τα tests κρυπτογράφησης παραλείπονται και η ζώνη ώρας διαφέρει. Και τα δύο PHP
φανέρωσαν πραγματικά bugs, αλλά το έγκυρο είναι του Local.

**Το git.** Σε **PowerShell** δουλεύει κατευθείαν, χωρίς τίποτα. Σε σκέτο **cmd**,
αν δεν το βρίσκει:

```
set PATH=%PATH%;C:\Program Files\Git\cmd
```

Αυτή η γραμμή είναι σύνταξη του cmd και **αποτυγχάνει στο PowerShell** — εκεί
θα ήταν `$env:PATH += ";C:\Program Files\Git\cmd"`. Μην την αντιγράψεις τυφλά.

**Πολυγραμμικά μηνύματα commit: πάντα με `-F`, ποτέ με `-m`.** Το PowerShell τα
δέχεται με συνέχιση `>>`· το cmd.exe **όχι** — κρατά μόνο την πρώτη γραμμή και
προσπαθεί να εκτελέσει τις υπόλοιπες ως εντολές. Γράψε το μήνυμα σε
`.commit-msg.tmp.txt` (είναι ήδη στο `.gitignore`) και:

```
git commit -F .commit-msg.tmp.txt
```

Δουλεύει και στα δύο shells, και λύνει μαζί και τα ελληνικά.

**Ο hook ΔΕΝ τρέχει τη σουίτα integration.** `composer check` = phpcs + phpstan
(level 6) + **unit**. Ο pre-commit hook τρέχει αυτό και μπλοκάρει το commit αν
αποτύχει — **πρέπει να είναι πράσινο**, αλλά πράσινο commit **δεν** σημαίνει
πράσινη σουίτα.

Ο αποκλεισμός είναι σκόπιμος (βλ. `TESTING.md`: όποιος δεν έχει στήσει βάση
πρέπει να μπορεί να κάνει commit). Σε συνδυασμό όμως με τον κανόνα «κάθε βήμα
αφήνει τη σουίτα πράσινη» είναι παγίδα: στις 2026-08-11 μια ολόκληρη μετακόμιση
(`777a1aa`) έγινε commit χωρίς να την έχει δει κανένα integration test, επειδή ο
hook πέρασε. Για **κάθε** commit του βήματος 10, τρέξε πρώτα:

```
composer check:all
```

**Οι μεταβλητές της βάσης δοκιμών χάνονται με το παράθυρο.** Κάθε νέο Site shell
ξεκινά χωρίς αυτές, και τότε το `composer test:integration` βγάζει «No test
database named» — που **δεν μοιάζει με αποτυχία test**, μοιάζει με σφάλμα
ρύθμισης, και είναι εύκολο να το προσπεράσεις. Στο ίδιο παράθυρο με τα tests:

```
set ECRM_TEST_DB_NAME=energy_crm_tests
set ECRM_TEST_DB_USER=root
set ECRM_TEST_DB_PASSWORD=root
```

Κατάσταση 2026-08-11: **164 unit + 74 integration**, phpstan καθαρό, phpcs
καθαρό — και πλέον το phpcs καλύπτει και τον legacy κώδικα (βλ. CHANGELOG).

Προσοχή στα skipped: σε PHP **χωρίς** sodium παραλείπονται 6 tests, όλα
κρυπτογράφησης. Αν δεις «6 skipped», έτρεξες με το λάθος PHP και τα tests που
προστατεύουν τα ΑΦΜ **δεν εκτελέστηκαν**. Από το Site shell του Local πρέπει να
μείνει 1.

## 4. Τι έχει γίνει — ασφάλεια και GDPR

Όλα ολοκληρωμένα, ελεγμένα, committed (`57484e5` και επόμενα).

| Κενό | Λύση |
|---|---|
| Η διαγραφή άφηνε πίσω IBAN, υπογραφές, leads, tasks, events | `src/Persistence/PersonalDataEraser.php` — όλοι οι πίνακες |
| Η εξαγωγή (Άρθρο 15) έδειχνε λιγότερα απ' όσα κρατάμε | `src/Persistence/PersonalDataExporter.php` |
| Οι δύο παραπάνω απέκλιναν μεταξύ τους | `src/Persistence/PersonalDataTables.php` — μία κοινή λίστα |
| Τα WordPress privacy tools απαντούσαν «δεν βρέθηκε τίποτα» | `src/Admin/PrivacyTools.php` |
| Παλιές σαρωμένες ταυτότητες πιθανώς δημόσιες | `src/Infrastructure/DocumentProtection.php` — cron ανά ώρα, παρτίδες 25, atomic claim |
| Rate limiting παρακάμψιμο με πλαστά headers | `src/Infrastructure/ClientIp.php` — trusted proxies, ανάγνωση αλυσίδας από δεξιά |
| Η συναίνεση δεν ανέφερε την AI επεξεργασία εγγράφων | `ECRM_Tracking::consent_text()` + φίλτρο `ecrm_consent_text` |
| PII σε καθαρό κείμενο | `FieldCipher` + `CustomerFields` + `ContractFields` + blind index |

**Κρυπτογράφηση — πώς δουλεύει:**

Στήλες `afm`, `adt`, `street`, `street_no`, `postal_code` του `customers`, και
οι προσωπικές τιμές μέσα στο `contracts.extra_json`. **Opt-in** με
`define('ECRM_ENCRYPT_PII', true)` στο `wp-config.php`· η ανάγνωση καταλαβαίνει
και καθαρό κείμενο και ciphertext, οπότε δεν υπάρχει ημέρα σημαία.

Επειδή η κρυπτογράφηση είναι τυχαιοποιημένη, το `WHERE afm = %s` δεν ταιριάζει
ποτέ. Γι' αυτό υπάρχει η στήλη **`afm_hash`** (keyed HMAC): κρατά ζωντανό τον
έλεγχο διπλοεγγραφών και την αναζήτηση με **πλήρες** ΑΦΜ. Η αναζήτηση με
**μερικό** ΑΦΜ χάνεται και δεν επανέρχεται.

Ισχύει μόνο για **νέες** εγγραφές — δεν υπάρχει backfill για τις υπάρχουσες.

**Ο κανόνας που διατρέχει τα πάντα:** `ProviderFormFields::isPersonalInput()`
είναι **default-deny** και χρησιμοποιείται σε τρία σημεία — διαγραφή, εξαγωγή,
κρυπτογράφηση. Πεδίο που δεν έχει ταξινομηθεί θεωρείται προσωπικό.

**Bugs που βρέθηκαν στην πορεία και διορθώθηκαν:**

- Σχόλια `--` μέσα στα `dbDelta` statements έσπαγαν **κάθε** ALTER. Αυτή ήταν
  η αιτία που το dbDelta «σιωπηλά αγνοούσε» αλλαγές και που υπήρχε το
  migration `EnsureLegacyColumns`. **Ποτέ ξανά σχόλια εκεί.**
- Οι κρυπτογραφημένες στήλες ήταν πολύ στενές (`afm VARCHAR(20)` για ~74
  χαρακτήρες ciphertext). Σε server χωρίς strict mode θα περιέκοπτε σιωπηλά =
  μόνιμη απώλεια ΑΦΜ. Migration `WidenEncryptedColumns`.
- `ContractTerm::endDate()` διάβαζε σε τοπική ώρα και έγραφε σε UTC: **κάθε
  ημερομηνία λήξης σε κάθε υπογεγραμμένη σύμβαση ήταν μία μέρα νωρίτερα** σε
  ελληνικό server.
- Το `FieldCipher` αποθήκευε **σιωπηλά καθαρό κείμενο** όταν έλειπε το
  libsodium — ψευδής αίσθηση προστασίας. Τώρα πετά `MissingCipher`.

**Σουίτα integration** (`composer test:integration`): πραγματικό WordPress σε
βάση μιας χρήσης. Καλύπτει scope enforcement, κρυπτογράφηση, διαγραφή. Το
bootstrap **αρνείται να τρέξει** αν η βάση δοκιμών είναι η ίδια με του site —
η βιβλιοθήκη δοκιμών κάνει DROP σε κάθε πίνακα.

### 6β. Κώδικας

- **Το άδειασμα του `ECRM_REST` — τα τελευταία δύο.** Ο κύκλος ζωής, το
  auto-process και η παραγωγή εγγράφων έφυγαν στις 2026-08-10, οι ειδοποιήσεις
  στις 2026-08-11· απομένουν, με σειρά προτεραιότητας:

  1. `can_manage_team()` — ένας καλούντας (`ECRM_Leads`), δύο γραμμές σώμα.
  2. `NS`, `init()`, `no_cache_headers()`, `routes()`. Το `routes()` είναι πια
     μόνο σχόλια, το `NS` διπλασιάζει το `Router::NAMESPACE` (ίδια τιμή,
     `ecrm/v1` — επαληθεύτηκε), και ο no-cache είναι HTTP — ανήκει στον `Router`.
     Μετά από αυτό το αρχείο σβήνεται.

## 7. Μέθοδος συντεταγμένων — μην την ξανα-ανακαλύψεις

Εγκεκριμένη από τον πελάτη, να μην αλλάξει:

1. `soffice --headless --convert-to pdf` το docx.
2. `pdftoppm -r 144 -jpeg` → υπόβαθρα 1191×1684 (A4).
3. `pdftotext -bbox-layout` → θέσεις ετικετών (`mm = pt × 25.4 / 72`).
4. Θέση τιμής: `y = ymin + 0.78 × (ymax − ymin) − 2.5`, όπου 2.5 =
   `ECRM_FormFill::BASELINE`. Το `x` λίγο μετά το τέλος της ετικέτας.
5. Κουτάκια και στήλες πινάκων: **ανίχνευση γραμμών από την εικόνα**, «Χ» στο
   κέντρο του κουτιού.
6. Υπογραφές: με μετρημένη απόσταση από το επόμενο κείμενο της σελίδας.

**Ποτέ με το μάτι πάνω σε εικόνα. Πάντα από κενή φόρμα** — υπόβαθρο από
συμπληρωμένο έντυπο μεταφέρει τα δεδομένα του πελάτη που το υπέγραψε.
