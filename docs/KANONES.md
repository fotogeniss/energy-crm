# Energy CRM — Κανόνες που δεν σπάνε ποτέ

Απόφαση ιδιοκτήτη 18/11/2026, μετά από τρεις ελέγχους που ο καθένας έβρισκε κάτι
καινούριο: «εφάρμοσε αυτούς τους κανόνες και γράψ' τους να ακολουθούνται ρητά».

Τα χειρότερα λάθη του CRM δεν ήταν μέσα σε μία λειτουργία αλλά ανάμεσα σε δύο
(«ξαναστείλε για υπογραφή» + «διαγραφή» = σβήσιμο αίτησης που πληρώθηκε). Γι' αυτό
κάθε κανόνας εδώ έχει τη λίστα με **όλες τις διαδρομές** που μπορούν να τον
σπάσουν, και κάθε διαδρομή έχει test.

## Διαδικασία (υποχρεωτική, σε κάθε αλλαγή)

1. **Πριν γραφτεί κώδικας:** διαβάζεται αυτό το αρχείο. Για κάθε κανόνα: «μπορεί η
   αλλαγή μου να τον παρακάμψει από διαδρομή που δεν είναι στη λίστα;».
2. **Νέα διαδρομή που γράφει, σβήνει ή αλλάζει κατάσταση/κάτοχο/αρχείο** μπαίνει
   στη στήλη «Διαδρομές» του κανόνα, με test, στην ίδια αλλαγή.
3. **Κάθε εγγραφή του CHANGELOG** από την (419) και μετά έχει γραμμή
   `**Κανόνες:** K1, K3` (ποιους αγγίζει) ή `**Κανόνες:** κανένας`. Το ελέγχει το
   `ChangelogNamesTheRulesTest`.
4. **Κάθε test που φυλάει κανόνα** έχει στο docblock του `@kanonas K#`. Το
   `EveryRuleHasATestTest` αποτυγχάνει αν κάποιος κανόνας μείνει χωρίς test ή αν
   ένα test δείχνει σε κανόνα που δεν υπάρχει.
5. **Έλεγχος («κάνε έλεγχο»)** = σενάρια με τα στραβά βήματα (διόρθωση, άδειασμα
   πεδίου, ακύρωση, ξανά-αποστολή, διπλό κλικ, άλλος χρήστης, μάνατζερ/Back office
   αντί για πωλητή), όχι μόνο ανάγνωση κώδικα. Ό,τι βρεθεί γίνεται test εδώ.
6. **Αλλαγή ή κατάργηση κανόνα** μόνο με ρητή απόφαση του ιδιοκτήτη, γραμμένη στον
   κανόνα με ημερομηνία.

## Οι κανόνες

### K1 — Η υπογραφή του πελάτη δεν σβήνεται και δεν πλαστογραφείται

Μόνο ο ίδιος ο πελάτης βάζει υπογραφή (σύνδεσμος παρακολούθησης). Πωλητής,
συνεργάτης και Back office δεν τη σβήνουν και δεν ανεβάζουν δική τους.

| Διαδρομή | Φύλακας |
|---|---|
| Ξανα-αποστολή για υπογραφή | `SignLinkController::refusalBeforeErasing()` (Ενεργή → μόνο admin· έλεγχος πριν το σβήσιμο) |
| Διαγραφή εγγράφου | `DocumentsController::destroy()` — `SystemKind::isSystem()` μόνο admin |
| Ανέβασμα εγγράφου | `DocumentsController::uploadKind()` — μόνο `ECRM_Docs::kinds()` |
| Αλλαγή είδους εγγράφου | `FileRepository::setKind()` — όχι από/προς είδος συστήματος |
| Ανέβασμα από τον πελάτη (παρακολούθηση, «σύνδεσμός μου») | λίστα ειδών στο `ECRM_Tracking`/`ECRM_Intake` |
| Διαγραφή αίτησης | K2 |
| Νέο έντυπο παρόχου μετά την υπογραφή (ξανατύπωμα με την υπογραφή) | `DeiCatalogue::PACKAGES_FROM`: ό,τι υπογράφηκε πριν, στο παλιό έντυπο |

### K2 — Ό,τι υπογράφηκε ή έγινε ποτέ Ενεργό δεν διαγράφεται

| Διαδρομή | Φύλακας |
|---|---|
| Διαγραφή μίας | `DeletionGate::refusalOnDelete()` (`signed_at` ή `hasReached(active)`) |
| Μαζική διαγραφή | ίδιο, ανά γραμμή |
| «Ειδική πύλη» | μόνο `manage_options`, με εγγραφή στο `deletion_log` |

### K3 — Μετά την υπογραφή, ό,τι υπέγραψε ο πελάτης δεν αλλάζει από μη-admin

Πάροχος, πρόγραμμα, είδος ενέργειας, πελάτης της αίτησης, ΑΦΜ.

**Απόφαση ιδιοκτήτη 19/11/2026:** «κλειδώνουν όλα τα τυπωμένα πεδία». Ό,τι
τυπώνει το έντυπο του παρόχου (`PrintedFields`, από τα ίδια template.json της
εκτύπωσης) δεν αλλάζει, ούτε γεμίζει αν ήταν κενό. Ισχύει και για τα στοιχεία
του πελάτη που τυπώνονται σε οποιαδήποτε υπογεγραμμένη αίτησή του. Εξαιρούνται
ο αριθμός αίτησης του παρόχου και η λήξη (`PrintedFields::OFFICE_FIELDS`), που τα
γράφει το γραφείο μετά την υπογραφή.

| Διαδρομή | Φύλακας |
|---|---|
| Αποθήκευση φόρμας | `SignedFieldsLock` στο `ContractSaveController` |
| Καρτέλα πελάτη (ΑΦΜ) | `CustomersController::updateFull()` + `customerHasSigned()` |
| Ανάγνωση εγγράφων (AI) | γεμίζει μόνο κενά (`ExtractionController::applyToRecords()`) |
| Ξανα-αποστολή που μηδενίζει το `signed_at` | K1 (Ενεργή → μόνο admin) |
| Τυπωμένα πεδία από τη φόρμα (και από άλλη αίτηση του ίδιου πελάτη) | `ContractSaveController::refusePrinted()` → `SignedFieldsLock::printedChange()` |
| Τυπωμένα στοιχεία από την καρτέλα πελάτη | `CustomersController::updateFull()` → `PrintedFields::onSignedContractsOf()` |
| Ανάγνωση εγγράφων (AI) σε τυπωμένα πεδία | `ExtractionController::applyToRecords()` — δεν γεμίζει ούτε κενά |

### K4 — Καμία κατάσταση εκτός γράφου, καμία φυλασσόμενη χωρίς χαρτιά και υπογραφή

Όλες οι αλλαγές κατάστασης περνούν από `ContractLifecycle::moveTo()`.

| Διαδρομή | Φύλακας |
|---|---|
| Αλλαγή κατάστασης (μία) | `ContractStatusController::change()` → `moveTo()` |
| Μαζική αλλαγή | `ContractsBulkController` → `moveTo()` |
| Αποθήκευση φόρμας με `status` | `ContractSaveController::refuseStatusChange()` → `moveTo()` |
| Εισαγωγή Excel παρόχου | `ECRM_Import` → `moveTo()` |
| Αποστολή για υπογραφή / υπογραφή πελάτη | `SignLinkController`, `ECRM_Tracking` → `moveTo()` |
| Έξοδος από πρόχειρο χωρίς ΑΦΜ | `DraftExitGate` (και ΑΦΜ που σβήνεται στην ίδια αποθήκευση) |
| Έξοδος από πρόχειρο χωρίς εγγύηση ΔΕΗ, αποστολή υπογραφής χωρίς εγγύηση ΔΕΗ | `DraftExitGate::guaranteeOnMove()`, `missingGuarantee()` (το 0 είναι ποσό) |
| Δικαιολογητικά Protergia (αιτήσεις από `ProtergiaDocs::FROM`) | `ECRM_Docs::checklist()` → `ProtergiaDocs` (ένα από, υπενθυμίσεις)· οι παλιότερες στον γενικό πίνακα |

### K5 — Η προμήθεια μετράει με έναν ορισμό και δεν αλλάζει μετά την πληρωμή

Πληρωτέα = έγινε ποτέ Ενεργή (`PayableClause`, `EventRepository::hasReached()`, ίδιος
ορισμός). Μήνας = ενεργοποίησης, αλλιώς υπογραφής, αλλιώς δημιουργίας. Πληρωμένη
παρτίδα δεν αλλάζει· εκκρεμής παρτίδα έχει σύνολα = άθροισμα γραμμών.

| Διαδρομή | Φύλακας |
|---|---|
| Ακύρωση σε εκκρεμή παρτίδα | `releaseFromPendingBatch()` + `refreshTotals()` |
| Ανάθεση σε άλλον / μεταφορά χαρτοφυλακίου με γραμμή σε εκκρεμή παρτίδα | `ContractRepository::reassign()`/`handOver()` → `releaseFromPendingBatch()` |
| Δημιουργία παρτίδας | `PayoutRepository::stampAmounts()` (guarded) |
| Διαγραφή παρτίδας | μόνο εκκρεμής |
| Αλλαγή προγράμματος μετά την υπογραφή | K3 |
| Διαγραφή προγράμματος/παρόχου (σβήνει κανόνες προμήθειας με CASCADE) | `ProviderRepository::deleteOrRetireProgram()`/`deleteOrRetireProvider()` — με αιτήσεις: απενεργοποίηση |

### K6 — Η αίτηση (και η προμήθεια) ανήκει σε όποιον ανήκει η πηγή της

Ο κάτοχος δεν έρχεται ποτέ από το αίτημα του browser.

| Διαδρομή | Φύλακας |
|---|---|
| Νέα αίτηση | `ContractRepository::create()` — ο δράστης |
| Μετατροπή lead | `createFor()` — ο κάτοχος του lead, αν είναι στο scope |
| Δίδυμη αίτηση (ρεύμα/αέριο) | `createFor()` — ο κάτοχος της αρχικής |
| Ανανέωση | ο δράστης (απόφαση: «όποιος ανανεώνει») |
| Αφαίρεση μέλους | στον μάνατζερ (απόφαση 06/09) |
| Ανάθεση / μεταφορά σε χρήστη εκτός CRM (συνδρομητής, απενεργοποιημένος, ανύπαρκτος) | `ContractRepository::isCrmUser()` — άρνηση |

### K7 — Ό,τι τυπώνεται στο έντυπο του παρόχου είναι ό,τι βλέπει ο πωλητής

| Διαδρομή | Φύλακας |
|---|---|
| Πεδίο που αδειάζει στη φόρμα | `data-loaded` στο `ecrm-form.js` + `customerFrom($params, $isUpdate)` |
| Ιδιώτης με παλιά επωνυμία | `customerFrom()` σβήνει `company_name`· `ECRM_FormFill` δεν την τυπώνει |
| Πεδίο που η φόρμα στέλνει πάντα (σημειώσεις, συναίνεση) | φορτώνεται στο `applyEdit()` — `FormLoadsWhatItAlwaysSendsTest` |
| Έντυπο ΔΕΗ μικρού/μεγάλου | `DeiCatalogue::LARGE_KVA` (≥ 35 kVA μεγάλος) |
| Πεδία του σάκου `extra` σε επεξεργασία | `ExtraFields::merge()` στο `ContractSaveController`: μένει ό,τι δεν στάλθηκε, φεύγει ό,τι στάλθηκε κενό |
| Διαγραφή προγράμματος/παρόχου (η αίτηση έμενε χωρίς πρόγραμμα, έντυπο, τιμή) | K5 — απενεργοποίηση |

### K8 — Κανείς δεν βλέπει ή αλλάζει κάτι εκτός του scope του

Κάθε διαδρομή με `{id}` περνά από `UserScope`/`ScopeClause`. Ανώνυμες διαδρομές μόνο
με HMAC token και όριο αιτημάτων.

### K9 — Δεδομένα πελατών δεν μένουν σε cache ή σε service worker

Εξαίρεση μόνο η ουρά νέας αίτησης εκτός σύνδεσης (απόφαση 08/09): ανά χρήστη, 48 ώρες.

### K10 — Πρώτα ελέγχεται αν επιτρέπεται, μετά σβήνεται ή γράφεται

Καμία ενέργεια δεν σβήνει αρχείο, υπογραφή ή γραμμή πριν βεβαιωθεί ότι ολόκληρη η
ενέργεια θα γίνει. Άρνηση = τίποτα δεν άλλαξε.

### K11 — Μία σύγκριση για κάθε ταυτότητα

ΑΦΜ: `ECRM_Validate::digits()` + blind index. Αριθμός παροχής: `SupplyNumber::key()`/`sql()`.
Τηλέφωνο: `PhoneNumber::key()` (ψηφία, χωρίς +30/0030) + blind index· κινητό και lead
(απλό κείμενο) με `PhoneNumber::sql()`/`likeTerm()`. Κανένας δεύτερος κανόνας «ίδιο ή όχι».

Ένας πελάτης ανά ΑΦΜ (434): η μετατροπή lead από το site με ΑΦΜ που υπάρχει δένει στον
ίδιο πελάτη (`LeadsController::convert()` → `findIdByAfm()`), όπως η αποθήκευση φόρμας.

Ο ίδιος κανόνας και στην αναζήτηση (421): `CustomerFields::afmSearchIndex()` (ΑΦΜ σε
ψηφία) και `ContractQueries::supplyLike()` (παροχή χωρίς κενά/παύλες), σε λίστα
αιτήσεων, λίστα πελατών και γρήγορη αναζήτηση.

### K12 — Μία ώρα

Η PHP με ώρα site (`current_time()`), η βάση με `NOW()`· ποτέ `UTC_TIMESTAMP()` απέναντι
σε στήλη ώρας βάσης. Η Υγεία δείχνει «Ζώνη ώρας» και «Ώρα βάσης και WordPress».

### K13 — Live και commit μόνο από τον ιδιοκτήτη

Τίποτα δεν ανεβαίνει στο live χωρίς ρητό «ανέβασε», και ανεβαίνει μόνο ό,τι έχει γίνει
commit. Commit/push κάνει μόνο ο ιδιοκτήτης. (Διαδικασία, όχι κώδικας· χωρίς test.)
