JS tests — τι φυλάνε σήμερα τα τρία PHP guard, τι δεν μπορούν να φυλάξουν, και τι ακριβώς μπαίνει

Ανοιχτό #3. Το approach δοκιμάστηκε και εκτελέστηκε σε sandbox αντίγραφο πριν γραφτεί οτιδήποτε στο repo — 19/19 tests περνάνε, μετρημένο, όχι υποτεθειμένο.

Η δόκιμη εντολή απόδειξης του §8.4 βγάζει δύο. Στην πραγματικότητα τρία PHP test σαρώνουν .js: το τρίτο, NoRemoteFontsTest, ελέγχει επέκταση με in_array($file->getExtension(), ['php','js','css'], true) — το 'js' είναι στοιχείο array, ποτέ η κυριολεκτική συμβολοσειρά .js, άρα το grep -rln "\.js\b" δεν το βρίσκει. Βρέθηκε τώρα, διερευνώντας αυτό το item — δεν είναι ακόμα στο §8, σημειώνεται εδώ ρητά ώστε να μη χαθεί πριν προστεθεί.

Και τα τρία διαβάζουν κείμενο, όχι κώδικα. Κανένα δεν import-άρει το αρχείο, δεν καλεί μια συνάρτηση, δεν ελέγχει τι επιστρέφει. Το ecrm-format.js λέει ρητά στο δικό του σχόλιο: «Pure functions, every one: same input, same output, no DOM, no network, no state.» Καμία εντολή μέχρι σήμερα δεν το είχε επαληθεύσει.

2. Το εμπόδιο, και η υπόθεση που διορθώθηκε

Τα public/assets/*.js γράφονται σκόπιμα ως ES modules (export function ...), φορτωμένα στον browser με native <script type="module"> — χωρίς bundler, χωρίς node_modules, χωρίς build artifact (ρητή σχεδιαστική επιλογή, σχόλιο στο ecrm-util.js). Δεν υπάρχει package.json πουθενά που να δηλώνει "type": "module". Χωρίς βοήθεια, ο Node θα τα διάβαζε ως CommonJS και θα έσκαγε στο πρώτο export.

Η αρχική σκέψη ήταν να χρειάζεται ρητά η σημαία --experimental-detect-module. Αυτό μετρήθηκε — σε sandbox αντίγραφο των τριών πραγματικών αρχείων, όχι στο repo — και διορθώθηκε: σε Node v22.22.2, το --help δείχνει μόνο τη σημαία που ΑΠΕΝΕΡΓΟΠΟΙΕΙ το detect-module, όχι αυτή που το ενεργοποιεί:

$ node --help | grep -A1 experimental-detect-module
  --no-experimental-detect-module
                              when ambiguous modules fail to evaluate

Δηλαδή το detect-module είναι ήδη προεπιλογή σε αυτή την έκδοση. Δοκιμάστηκαν και τα τρία, στο ίδιο sandbox, με τα ίδια 19 tests:

ΕντολήΑποτέλεσμα
node --test tools/js-tests/*.test.js (χωρίς σημαία) 19/19 περνάνε — ήδη ενεργό ως προεπιλογή
node --experimental-detect-module --test ... 19/19 περνάνε — ρητά ενεργό
node --no-experimental-detect-module --test ... σκάει στο πρώτο import
$ node --no-experimental-detect-module --test tools/js-tests/*.test.js
SyntaxError: Named export 'energyLabel' not found. The requested module
'../../public/assets/ecrm-format.js' is a CommonJS module, which may not
support all module.exports as named exports.

Η τρίτη γραμμή είναι η απόδειξη ότι η σημαία κάνει πραγματικά κάτι — δεν είναι no-op σε αυτή την έκδοση Node, απλώς η προεπιλογή ήδη συμφωνεί μαζί της. Η σημαία μένει ρητή στο npm test, γιατί (α) είναι ακόμα χαρακτηρισμένη "experimental" — η προεπιλογή θα μπορούσε να αλλάξει σε μελλοντικό Node — και (β) σε Node 20.19–21.x υπάρχει μόνο πίσω από ρητό flag, όχι ως προεπιλογή. Δεν μετρήθηκε πραγματικά σε 20.x/21.x — μόνο στην v22.22.2 του sandbox.

Καμία αλλαγή στο public/assets/. Καμία στιγμή δεν χρειάστηκε package.json εκεί ή αλλαγή στα ίδια τα production αρχεία — μόνο ένα νέο package.json μέσα στο tools/js-tests/, που δηλώνει "type": "module" για τα ΔΙΚΑ ΤΟΥ test files (δεν αγγίζει τη γειτονιά κάτω από public/, που δεν έχει κανέναν πρόγονο package.json).

3. Τι ακριβώς μπαίνει, και τι δοκιμάστηκε

Πέντε νέα αρχεία, όλα σε tools/js-tests/. Κανένα δεν αγγίζει PHP, κανένα δεν αγγίζει production JS.

format.test.js — 12 test up(), energyLabel(), fmtDate(), timeAgo(), initials(), tint(), svgIcon() Regression για το ακριβώς αντίστροφο λάθος της (84)/(89): αν κάποιος ξαναπροσθέσει + 'Z', ένα timestamp μορφοποιημένο ΤΩΡΑ (τοπική ώρα) θα φαινόταν στο μέλλον, το Date.now() - d θα πήγαινε αρνητικό, και το test θα έσκαγε αντί για «μόλις τώρα».

4. Τι ΔΕΝ λύνει

  • Δεν αντικαθιστά τα τρία PHP guard. Αυτά ελέγχουν πράγματα εντελώς διαφορετικά (fonts, HTML-escaping, timezone-reading-σε-ένα-σημείο) — δεν είναι διπλότυπα, μένουν όλα.
  • Δεν καλύπτει views, wizard, ή DOM-συνδεδεμένο κώδικα. Μόνο τα τρία module χωρίς κατάσταση/με απλή κατάσταση. Το tools/wizard-smoke/ καλύπτει το wizard ξεχωριστά και δεν αντικαθίσταται.
  • Δεν μπαίνει στο composer check:all. Ίδια απόφαση με το tools/wizard-smoke/ — το tools/ είναι ήδη εκτός scope για phpcs/phpstan/unit/integration. Δεν αλλάζει κανέναν από τους τέσσερις παρακολουθούμενους αριθμούς.
  • Δεν μπαίνει (ακόμα) στο .github/workflows/ci.yml. GitHub Actions runners έχουν Node προεγκατεστημένο, οπότε είναι εφικτό με μία ακόμα εντολή στο yml — αλλά είναι ξεχωριστή απόφαση, δεν προτείνεται εδώ ως μέρος αυτής της παρτίδας.
